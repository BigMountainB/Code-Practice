# Davis Plumbing — Website

A fast, modern, SEO-first marketing website for **Davis Plumbing, Inc.** — a
family-owned plumbing contractor serving Renton, Kent and the greater Seattle
area. Built to position Davis Plumbing as a premier custom-home and remodel
plumbing craftsman, not another generic plumbing service.

- **Zero-runtime-dependency** static site (hand-built HTML5 / CSS / vanilla JS)
- Generated by a small **zero-dependency Node build script** (`build.mjs`)
- **22 pages**: home, about, services (+4 detail pages), gallery, service areas
  (+8 city landing pages), reviews, contact, request-an-estimate, brand, 404
- Self-hosted variable fonts, inline SVG icons, JSON-LD schema on every page
- Three original **logo concepts** + full brand suite in scalable SVG

---

## ⚠️ Important: how the original site content was gathered

This project was built in a sandboxed environment whose **network policy blocks
`davisplumbing.com` and the Internet Archive** (both returned HTTP 403). As a
result, the original site's HTML and photography **could not be scraped or
downloaded directly**.

Instead, all business content was **reconstructed from public records and
directory listings** (WA Secretary of State / L&I, BuildZoom, Yelp, Birdeye,
BBB, ZoomInfo) and rewritten into modern, SEO-friendly copy. Two things follow
from that, and both are easy to finish:

1. **Real photography still needs to be added.** The site is fully designed and
   looks finished using on-brand placeholders that swap for real photos
   automatically. See **[`assets/img/README.md`](assets/img/README.md)** — drop
   the original project photos in at the listed paths and rebuild.
2. **A few facts should be verified** before going live (see
   [Content to verify](#content-to-verify)).

If you can provide the original site export (or a folder of the project
photos), they slot straight in — the alt text and gallery categories are
already written.

## Quick start

```bash
npm run build     # generate all pages + sitemap/robots/manifest
npm run serve     # preview at http://localhost:8080
npm run dev       # build + serve
```

No dependencies are required to build or serve. (Node 18+.)

## Project structure

```
/                       ← generated HTML output (deploy this) + assets
├── index.html, about/, services/, service-areas/, gallery/ …   (generated)
├── sitemap.xml, robots.txt, site.webmanifest                   (generated)
├── assets/
│   ├── css/styles.css        ← the entire design system (one file)
│   ├── js/main.js            ← nav, reveal, gallery lightbox, forms
│   ├── fonts/                ← self-hosted Fraunces + Inter (variable woff2)
│   ├── logos/                ← 3 logo concepts + full brand suite (SVG + PNG)
│   └── img/                  ← placeholders/ (generated) + real photos (add)
├── build.mjs              ← static site generator (zero deps)
├── scripts/
│   ├── placeholders.mjs   ← generates on-brand SVG image placeholders
│   ├── gen-icons.mjs      ← generates PNG favicons + OG card (run once)
│   └── serve.mjs          ← tiny preview server
└── src/
    ├── data/              ← site.mjs (business facts) + areas.mjs (cities)
    ├── lib/               ← templates.mjs (layout, schema) + icons.mjs
    └── pages/             ← one module per page / page-group
```

### The single source of truth

Almost everything — phone number, address, services, reviews, city content —
lives in **`src/data/site.mjs`** and **`src/data/areas.mjs`**. Change a fact
once there and it updates across every page, the footer, and the schema markup.

## Adding future content (built for growth)

- **A new service page** → add an entry to `services` in `src/data/site.mjs`
  and a detail block in `src/pages/service-detail.mjs`. Nav, cards, sitemap,
  and schema update automatically.
- **A new city landing page** → add an entry to `areas` in
  `src/data/areas.mjs`. A fully-templated, schema-rich page is generated.
- **A new gallery photo / category** → edit `galleryItems` /
  `galleryCategories` in `src/data/site.mjs`.
- **A blog** → add `src/pages/blog.mjs` returning an array of page descriptors;
  the build already supports one-module-many-pages.

## SEO & performance

- Unique `<title>` + meta description + canonical on every page
- Open Graph + Twitter Card tags; generated 1200×630 OG image
- **JSON-LD schema**: `Organization` (sitewide), `Plumber`/`LocalBusiness`,
  `Service`, `FAQPage`, `BreadcrumbList`, `Review` + `AggregateRating`
- `sitemap.xml`, `robots.txt`, `site.webmanifest` generated on every build
- Self-hosted preloaded variable fonts (`font-display: swap`), lazy-loaded
  images with width/height + `aspect-ratio` (no layout shift), `fetchpriority`
  on hero images, deferred JS, a single small CSS file — tuned for green
  Core Web Vitals.
- Accessibility: skip link, semantic landmarks, focus-visible styles, keyboard
  gallery/lightbox, `prefers-reduced-motion` honored, ARIA on nav & dialogs.

## Connecting the forms

The Contact and Request-an-Estimate forms validate client-side and show a
success state, but **no backend is wired** (a static site has no server). Pick
one and edit the marked block in `assets/js/main.js`:

- **Formspree / Basin / Getform** — set the `<form action>` to your endpoint
  and let it submit normally, or `fetch()` POST it.
- **Netlify Forms** — add `netlify` + a hidden `form-name` field.
- **Email/CRM** — POST to your own function (e.g. AWS Lambda, Cloudflare
  Worker) and forward to email or your CRM.

## Deploying

The repo root **is** the deployable site. Any static host works:

- **GitHub Pages** — serve from the branch root (a `.nojekyll` file is
  included). Point your custom domain at it.
- **Netlify / Vercel / Cloudflare Pages** — build command `npm run build`,
  publish directory `.` (root).

Set the production URL once in `src/data/site.mjs` (`site.url`) so canonical
tags, sitemap, and schema use the right domain.

## Content to verify

Marked `VERIFY:` in `src/data/site.mjs`. Confirm with the owner before launch:

- **Email address** — a public inbox (directory shows an `@davisplumbing.com`
  owner address).
- **Hours of operation** — a sensible default is set; confirm real hours.
- **WA L&I license/registration number** and bond — add to `business.license`.
- **Geo coordinates** — approximate Renton HQ coordinates are set for schema.
- **Reviews** — three testimonials are paraphrased from genuine public reviews
  (marked `verified: true`); the rest are representative placeholders. Replace
  with real, attributable reviews before relying on `Review`/`AggregateRating`
  schema (Google requires genuine, sourced ratings), and confirm the aggregate
  rating value/count.
- **Social links** — add Facebook/Instagram/Google Business Profile URLs.
